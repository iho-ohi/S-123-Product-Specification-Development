<title id="_214548c5-0ce7-ce7e-2f38-03688eea79fa">Domain model</title>
<p id="_f5dd4912-6ccc-452a-6088-f772ad8a5cbe">The S-123 domain model has two base classes (’root classes’) from which all the domain-specific geographic features and information type classes are derived. The base classes are shown in  <xref target="fig_4-1"/> below. The base class for geographic features is  <strong>FeatureType</strong> and the base class for information types is  <strong>InformationType</strong>. Each of the two base classes has a set of attributes which are therefore inherited by all domain-specific features. Both base classes are abstract classes and do not have direct instances in S-123 data — instead, S-123 feature and information type data objects are instantiations of a non-abstract class derived from one of these base classes.</p>

<p id="_6e4b3aa7-14a1-7719-2c2e-d911e9ad7cac">S-123 meta- features are not derived from these base classes — S-123 instead incorporates meta- and cartographic feature definitions originally prepared for S-101 in the interests of harmonization and interoperability with other S-100-based data products, especially S-101 ENCs.</p>

<title id="_34d1f7a1-caa0-51d1-b02e-8cad2dbb5e31">Feature types</title>
<p id="_c7a73fe0-2dce-ce3c-c8e5-d53cda1c6c21">Feature types contain descriptive attributes that characterize real-world entities. The word ‘feature’ may be used in one of two senses — feature type and feature instance. A feature type is a class and is defined in a Feature Catalogue. A feature instance is a single occurrence of the feature type and represented as an object in a dataset. A feature instance is located by a relationship to one or more spatial instances. A feature instance may exist without referencing a spatial instance.</p>
